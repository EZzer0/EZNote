# 抖音网页打开缓慢排查记录

> [!success] 排查与修复效果
> 现象：`https://www.douyin.com/?recommend=1` 打开缓慢，其他网页正常
> 根因：WLAN 手动静态 DNS 挂了 `8.8.8.8`（国内实测 700ms–3s、部分超时）
> 修复后：冷缓存解析 **12–26ms**，用户确认问题解决
> 记录：2026-09-28 排查 · 2026-10-02 整理

---

## 一、结论先行

网络链路到抖音是**好的**（ping 20ms、TTFB 0.14s、headless 完整加载 ~1s，与百度/B站同档），慢在**浏览器侧 + DNS 配置隐患**：

| #   | 发现                                                                                                      | 严重度     | 处置                                       |
| --- | ------------------------------------------------------------------------------------------------------- | ------- | ---------------------------------------- |
| 1   | WLAN 静态 DNS = `114.114.114.114 + 8.8.8.8`，8.8.8.8 国内实测 710ms–1684ms、部分查询 3s 超时；一旦 114 应答失败就由它兜底，把解析拖进秒级 | 主因      | ✅ 已改 `192.168.1.1 + 114.114.114.114`     |
| 2   | 本机 UDP/443 出站疑似被静默丢弃 → Edge 先试 h3 超时再回退 TCP；叠加 Edge 冷启动后台请求（微软/谷歌 ~1.4s）                                | 次因      | ⏳ 遗留（`edge://flags` 关 `#enable-quic`，未动） |
| 3   | 抖音返回 72KB 反爬 JS 挑战页（jsvmprt）+ 人机验证（verify.snssdk.com captcha），比普通页面多两轮往返                                | 固有      | 不处理                                      |
| 4   | Edge 因系统 DNS 含 8.8.8.8 而自动走 `dns.google` DoH 升级（国内不通）                                                   | 随 #1 消失 | ✅ 移除 8.8.8.8 后路径消失                       |
|     |                                                                                                         |         |                                          |

## 二、分层排查过程

### 1. 链路层 —— 正常

```text
ping www.douyin.com → CNAME → 27.195.146.72（山东联通，via: CHN-SDqingdao-CUCC26）
延迟 18–26ms，0% 丢包
```

### 2. 传输/TLS 层 —— 正常（首 TLS 1.45s 为一次性）

```text
curl 逐段计时：DNS 17ms · TCP 37ms · TLS 首次 1.45s（后续新进程均 0.05–0.08s）· TTFB 0.11–0.14s
72KB HTML 总耗时 ~0.17s；百度/QQ/哔哩 TTFB 同档（0.10–0.16s）
```

> [!note] 首次 TLS 1.45s
> 仅第一次出现，后续每次新进程连接都 ~170ms → 判定为冷握手/证书吊销检查（OCSP/CRL）的一次性开销，非持续问题。

### 3. MTU / IPv6 —— 排除

| 项 | 实测 | 判定 |
| --- | --- | --- |
| PMTU | `ping -f -l 1464` OK、`1472` DF fail → 路径 MTU ~1492 | 与百度一致，**非抖音特有**（PPPoE 类路径特征） |
| IPv6 | DNS 有 AAAA（2408:…），但 WLAN `ms_tcpip6` 绑定关闭、无 v6 默认路由；TcpClient 连 v6 **35ms 立即失败**；Chromium netlog `ipv6_available: False` | 快速跳过，**非主因** |

### 4. 浏览器层 —— headless 实测抖音不慢

| 站点 | headless Edge 完整加载（warm） |
| --- | --- |
| 抖音 | ~1.0–1.2s |
| 百度 | ~0.9–1.6s |
| 哔哩哔哩 | ~2.4–2.8s |
| 知乎 | ~2.8–3.8s |

netlog 分析：DNS 17–25ms、主文档 143ms、**无 >60ms 空洞**；占时间的是 Edge 自身后台请求（edge.microsoft.com / clients2.google.com 各 ~1.4s，仅冷启动）。

- 反爬证据：netlog 出现 `verify.snssdk.com/captcha`、`rmc.bytedance.com/verifycenter` → 页面先发 JS 挑战再进人机验证，首屏天然慢一拍
- QUIC 证据：`QUIC_SESSION_POOL_JOB` 存在但**无 QUIC_SESSION 建立**，主文档走 h2；对抖音/百度/QQ IP 的 UDP 443 探测均无回包（B站 IP 返回 ICMP port unreachable）→ 出站 UDP/443 被静默丢弃嫌疑

### 5. DNS 层 —— 找到根因

| DNS 服务器 | A 记录 | AAAA 记录 |
| --- | --- | --- |
| `114.114.114.114` | 213ms（冷）→ 15ms（热） | 17ms |
| `8.8.8.8` | **710ms** | **1684ms**（部分 3s 超时） |
| `192.168.1.1`（网关） | **9–20ms** | 10ms |

- WLAN DNS 是**手动静态配置**（DHCP 本该下发 `192.168.1.1`）
- 抖音页面横跨几十个 CDN 主机名（douyinpic / douyinvod / bytecdntp / snssdk / zijieapi…），每个冷解析都要过一遍 DNS → 慢 DNS 被乘数放大；其他网页主机名少、多在缓存里，所以"没事"
- 代理排除：`ProxyEnable=0`、7890 无监听、无 TUN 适配器 → 直连，FlClash 未干扰

## 三、修复操作

```powershell
# 提权 netsh 静态覆盖（原配置即手动静态；CIM/netsh 普权限均被拒 → Start-Process -Verb RunAs 弹 UAC）
netsh interface ipv4 set dnsservers "WLAN" static 192.168.1.1 primary
netsh interface ipv4 add dnsservers "WLAN" 114.114.114.114 index=2

ipconfig /flushdns
```

| 项 | 改前 | 改后 |
| --- | --- | --- |
| WLAN DNS | 114.114.114.114 + **8.8.8.8** | **192.168.1.1** + 114.114.114.114 |
| 冷缓存解析 | 8.8.8.8 路径 700ms–3s | **12–26ms**，无超时 |
| Edge DoH | 自动尝试 dns.google（不通） | 路径随 8.8.8.8 移除而消失 |

> [!tip] 想撤销 / 交还 DHCP
> `Set-DnsClientServerAddress -InterfaceAlias WLAN -ResetServerAddresses`（需管理员）

**用户反馈**：2026-09-30「我不知道你干了什么 但是确实解决了我的问题」。

## 四、想法 / 方法论

1. **分层证伪，不猜**：链路 → 传输/TLS → MTU/IPv6 → 浏览器（headless 对比 + netlog）→ DNS，每层先证明或排除再进下一层。
2. **一切结论指得回一条命令输出**：首 TLS 1.45s 差点误判为主因，后续 5 次新进程实测均 170ms 才修正为"一次性"。
3. **"其他网页没事"是关键约束**：不找绝对性能，找**差异项**（8.8.8.8 兜底、几十个 CDN 主机名、反爬挑战、UDP/443 回退）。
4. **探测工具本身会骗人**：手写 DNS UDP 包 label 前误插 0 字节 → 整批 raw 测试作废；自造 QUIC 畸形包无回包 ≠ UDP 被墙（服务器本就该忽略）—— 证据强度要分档标注。
5. **失败即换手段**：CIM 拒绝 → netsh 拒绝 → `Start-Process -Verb RunAs` 提权，同一方法不硬试第三次。
6. **临时文件纪律**：探测生成的脚本/netlog/headless profile 用完即清，真实进程与用户配置全程只读不碰。
